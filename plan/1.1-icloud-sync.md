# 1.1 — iCloud sync (next iteration)

Status: planned, 2026-09-09. Follows the 1.0 App Store release; builds on the shared
`UtterclipCore` and the Mac app. Decisions are recorded at the end; phase 1 can start.

> Goal: a dictation made on the Mac shows up in the iPhone's History (and the other way
> round), the API key is entered once, and custom styles and settings follow the user — with
> no account of ours, no server of ours. Everything rides on the iCloud account both devices
> are already signed into. Target: version 1.1, after 1.0 clears review.

## What syncs, and how

| Data | Today | Sync mechanism | Why this one |
|---|---|---|---|
| History (≤200 entries: id, date, raw, styled, styleID) | `history.json` in Application Support, `HistoryStore` | **SwiftData model with CloudKit** (private database, container `iCloud.com.ralfchille.voicer`) | Least code for a flat record type; Apple handles transport, offline queueing, conflicts, encryption. Both apps read the same container. |
| API key | Keychain, `ThisDeviceOnly`, per-app access group | **iCloud Keychain**: item marked `kSecAttrSynchronizable`, accessibility `AfterFirstUnlock`, in a **shared keychain access group** | End-to-end encrypted by Apple; the one place a secret belongs. The shared group is what lets the iPhone app and the Mac app (different bundle ids) see the same item. |
| Custom styles, overrides, deleted defaults, default style, copy-as-markdown, redaction | `UserDefaults` (7 keys) | **`SyncedSetting` records in the same CloudKit store as history** (one per key, newest wins), `UserDefaults` kept as the local cache | Planned as the iCloud key-value store, changed during phase 4: the key-value store rides on iCloud Drive, which a managed Mac can have switched off by policy (this one does). CloudKit does not depend on it. The on-device-model toggle stays per device: its availability differs between devices. |

Not synced: the Whisper model cache (re-downloadable, excluded from backup already), the
Mac window position, and "floatOnTop" (per machine by nature).

Already there for free: **Universal Clipboard.** Copy on one device, paste on the other within
about two minutes. Worth a README line; sync extends it rather than replacing it.

## Architecture changes

### History → SwiftData + CloudKit

- New `@Model final class Dictation` in `UtterclipCore` mirroring `HistoryEntry`. CloudKit rules:
  every property has a default or is optional, no `@Attribute(.unique)`, no non-optional
  relationships. `id: UUID` stays as a plain attribute (uniqueness is by convention).
- `HistoryStore` keeps its public surface (`entries`, `add`, `update(id:)`, `delete(at:)`,
  `delete(id:)`, `clear`) so the views and `RecorderViewModel` do not change. Internally it owns a
  `ModelContainer` (`cloudKitDatabase: .automatic`) and refreshes `entries` from a fetch, sorted by
  date, on its own writes and on `NSPersistentStoreRemoteChange` notifications from the store.
- Cap: still 200, enforced globally by date after every refresh (oldest deleted; deletions
  propagate). If the user has 200 on each device the merged set is 400 at first sync and the cap
  trims it — acceptable, and it happens once.
- Edits (`applyRawEdit`, `applyStyledEdit`) are last-writer-wins; there is no realistic
  concurrent edit of the same entry on two devices.

### API key → iCloud Keychain

- `KeyProvider` adds `kSecAttrSynchronizable = true` and `kSecAttrAccessGroup =
  "<TeamID>.com.ralfchille.voicer.shared"` to every query; accessibility becomes
  `kSecAttrAccessibleAfterFirstUnlock` (the `ThisDeviceOnly` variants cannot sync).
- One-time migration on first launch of 1.1: read the old item (non-synchronizable, per-app
  group), write it as the new item, delete the old one. Users never re-enter the key.
- macOS: synchronizable items live in the data-protection keychain only. The iCloud entitlements
  bring a provisioning profile and with it the application identifier, so the Mac app now takes
  the data-protection path for real; the login-keychain fallback stays for unsigned local builds
  (those simply do not sync).

### Styles and settings → iCloud KV store

- `StyleStore` and `RecorderViewModel` read/write through a small `SyncedDefaults` wrapper:
  write to `UserDefaults` and `NSUbiquitousKeyValueStore`, read `UserDefaults`, and on
  `NSUbiquitousKeyValueStore.didChangeExternallyNotification` copy the changed keys into
  `UserDefaults` and notify the stores. Key names unchanged.
- First launch of 1.1: if the KV store has values, they win over local `UserDefaults`
  (the other device already synced); else local values are pushed up.

### Entitlements (`Project.swift`), both app targets

```
com.apple.developer.icloud-container-identifiers   [iCloud.com.ralfchille.voicer]
com.apple.developer.icloud-services                 [CloudKit]
keychain-access-groups                              [$(AppIdentifierPrefix)com.ralfchille.voicer.shared]
aps-environment                                     development / production (CloudKit push for remote changes)
```

The widget extension needs none of this. The Mac target keeps its sandbox entitlements.

### Settings UI

- New section **iCloud**: one toggle, "Sync history, styles and API key with iCloud", **on by
  default** when an iCloud account is present. Off means: local SwiftData store without CloudKit,
  KV store not consulted, key stored non-synchronizable. Footer text explains that everything
  stays inside the user's own iCloud account, encrypted, and that the developer has no access.
- Status line under the toggle: "Not signed in to iCloud" when `FileManager.ubiquityIdentityToken`
  is nil.

## Migration and first sync

1. Launch 1.1: import `history.json` into SwiftData once (flag in `UserDefaults`), then rename
   the file to `history.json.migrated` (kept one release as a safety net).
2. Key: migrate as described. Styles/settings: KV-store-wins rule as described.
3. Two devices each with local history: the union appears on both; ids differ so nothing is
   lost or merged wrongly.

## Privacy and store copy

- `PRIVACY.md` and the README gain a section: what syncs, that it lives in the user's iCloud
  (Apple's encryption, developer has no access), and how to turn it off.
- App Store privacy answer stays **Data Not Collected**: Apple's definition concerns data the
  developer or its partners can access; iCloud sync is the user's own storage.
- Review notes: mention the toggle so the reviewer is not surprised by an iCloud prompt.

## Risks and how they are handled

- **SwiftData CloudKit sync on iOS 17** has known rough edges (occasional slow first sync,
  duplicate-prevention is on us). Data here is flat and append-mostly, which is the easy case. If
  it misbehaves in testing, fallback is `CKSyncEngine` (iOS 17+, more code, same entitlements) —
  the store's public API means the views would not notice.
- **Forgetting to deploy the CloudKit schema** to Production is the classic failure: everything
  works in Debug, nothing syncs in TestFlight. It is a checklist item in phase 6.
- **Shared keychain group + iCloud Keychain on macOS** requires the app to be signed with a
  profile; ad-hoc local builds silently fall back to the login keychain and do not sync. Already
  the case today; documented in the README's local-build note.
- **User has iCloud Keychain off** (some do): the key then behaves as today, per device. Settings
  footer says so.
- **Promise change**: "history stays on your phone" becomes "…or in your iCloud, if you choose".
  The toggle keeps the old behaviour available; the copy is explicit.

## Decisions (Ralf, 2026-09-09)

1. **Sync is on by default** whenever an iCloud account is present; the Settings toggle turns it off.
2. **The history cap stays at 200** entries, enforced globally by date after every sync.
3. **The API key syncs too**, through iCloud Keychain in the shared access group.
4. **Ships as 1.1**, together with the changes already on `main` since 1.0 (3): edit-rewrite,
   always-visible style pills, Plain as the starting style, whole-circle tap targets, the Icon
   Composer icon and the Mac app. Work happens on the `feature/icloud-sync` branch; version 1.1,
   build 4.
