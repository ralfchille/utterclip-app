# Utterclip 1.1 — what is left before release

Written 2026-09-11. Everything below sits on `feature/icloud-sync`, which is 74 commits
ahead of `main`. Both devices run current builds; nothing here is urgent, and nothing is
half-finished in the code.

## Do these in order

### 1. Deploy the CloudKit schema to Production
The only step that cannot be undone easily, and the one that blocks a real release: the
schema so far exists only in the Development environment.

- CloudKit Console → container `iCloud.com.ralfchille.voicer` → **Deploy Schema to
  Production**.
- What ships with it: the record types Core Data mirrors (`CD_Dictation`, including the
  `CD_originDevice` field added in 1.1, and `CD_SyncedSetting`) **plus the custom
  `UtterclipLive` zone and its `LiveState` record type**, which the Mac's phone indicator
  reads directly. The live zone is created by the app at runtime, so check it is present in
  Development before deploying.
- `CD_DeviceActivity` is still in the Development schema from an abandoned approach. It is
  harmless; leave it rather than risk an edit.
- Verify afterwards with a phone dictation appearing on the Mac from a Release build.

### 2. Privacy policy and App Review notes
- `PRIVACY.md` has no paragraph about sync yet. It needs to say: history, rewrite styles,
  settings and the API key travel through the user's own iCloud account (CloudKit private
  database and iCloud Keychain), nothing passes through a server of ours, and turning
  **Settings → iCloud → Sync with iCloud** off keeps everything local.
- `docs/app-store/listing.md` review notes need the same, plus a line about the Mac app's
  Accessibility usage if the Mac ever goes to review. Its `<<< TEST KEY >>>` placeholder
  still needs a real key at submission time, to be revoked after approval.

### 3. Merge and ship the iPhone build
- Merge `feature/icloud-sync` into `main`.
- `MARKETING_VERSION` is 1.1 and `CURRENT_PROJECT_VERSION` is 4 already.
- Archive in Xcode and upload through **Organizer** — `xcodebuild -exportArchive` cannot see
  the Xcode account from a shell and fails with "Failed to Use Accounts".
- TestFlight, then submit.

## Decision waiting to be made

**The Mac app is no longer sandboxed** (commit `e7ede56`). It had to be: a sandboxed app is
granted Accessibility and then fails every cross-process call, so the global shortcut could
neither find the focused text field nor paste back. Consequence: the Mac app cannot go to the
Mac App Store as it stands. If that was ever the plan, either accept direct distribution
(notarised Developer ID) or put the sandbox back in `Project.swift` and drop the shortcut's
placement and paste-back. Nothing else about the privacy story changes — transcription is
still on-device.

## Things that are done, so they do not surprise you

1.1 grew well past iCloud sync. On the Mac: a global shortcut (⌃⌥⌘Space) that opens the
window at the caret and pastes the result back into the app you were in, as a confirm step
rather than automatically; History, Settings and the editor sliding up as panels; two window
sizes; a phone-activity indicator fed by a live CloudKit zone. On both: Markdown as a
per-style setting, the editor at the result view's type sizes. The Figma file's "Mac app"
page documents the Mac design.

## Two traps worth remembering

- **A full phone makes the app look broken.** iOS caches the model's Neural Engine
  compilation in the app's Caches folder; with no free space the write fails silently and
  every cold launch recompiles. Measured 24 s, once 249 s, against 3.5 s normally. There is
  a FAQ entry about it.
- **Changing the Mac target's entitlements invalidates its Accessibility grant**, and the
  failure is silent. Remove Utterclip from System Settings → Privacy & Security →
  Accessibility and add it again.
